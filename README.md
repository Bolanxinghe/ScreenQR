# ScreenQR · 屏幕扫码

Windows桌面取景扫码工具。普通网页码确认后在默认浏览器打开；微信专用码自动尝试交给本机已登录微信。无需手机或模拟器。

官方仓库：[Bolanxinghe/ScreenQR](https://github.com/Bolanxinghe/ScreenQR)。源码已公开，EXE 发行版正在准备，尚未正式提供下载。普通用户的完整便携包将在 [Releases](https://github.com/Bolanxinghe/ScreenQR/releases) 提供；[自动构建状态](https://github.com/Bolanxinghe/ScreenQR/actions/workflows/windows.yml) 可公开查看。

当前为 **0.10.1-rc1 发布候选版**。保留本机历史记录、常见一维条码、结果按钮和多码点选，补充程序内四页帮助、环境报告和整包校验。微信校准与严格门禁保留；尚未扩展到第二套微信环境。构建事实见 `docs/build-info.json`，真机验收及未测范围见本版验收报告；不同 EXE 的结论不得混用。

## 使用

双击ScreenQR.exe，保留同目录_internal文件夹。拖动取景窗口顶部，将完整二维码和周围留白放进框内；窗口边缘可调整大小，系统关闭入口退出程序。

- 普通网页码显示小预览和可滚动的完整网址。点击“在浏览器打开”前不会访问目标；“复制”保留原文。点击后重新读取当前画面，目标、位置或内容变化则旧确认失效；确认前不会打开浏览器。
- 微信专用码稳定读取后自动交给微信。圆形小程序等通用解码器读不出的图形，框住唯一目标后松手会尝试微信原生识别，不需要勾选或点击微信识别。
- 交给微信后等待下一次选码，避免扫描业务页里的其它二维码，也避免把已打开的流程重新显示为失败。重新拖动、缩放取景框，或按空格即可继续；取景框会让出微信页面。
- 多个码时可以点列表选一个，再看清网址后打开；也可以缩小取景框。相同内容的两个码分别列出，不会默认选第一项。其它码的内容或位置变化也撤销旧确认，微信仍要求框成唯一目标。
- 不可读取或不支持时显示“没扫出来”。微信交付后尚未核验页面时会明确写“页面尚未确认”，不能据此宣称业务成功。
- 微信登录码按实际内容分流。已确认的open.weixin.qq.com/connect/confirm格式不交给外部浏览器；微信实际返回仅支持摄像头提示时，显示当前方式不支持。不会因网址属于这个家族就预先断言它一定过期或一定不支持。

低频能力保留快捷键：Ctrl+O读取本地图片，Ctrl+C复制唯一识别内容，空格暂停/继续，Esc退出。选图后拖动取景窗口即可返回屏幕扫描。顶栏“历史”可看最近 100 条的全文、复制或打开通过门禁的网址，可清空或停止保存新记录。关闭记录后已有记录仍可手动清空。记录不在便携包内，付款码不保存。F1 或顶栏右键打开程序内帮助，用户无需阅读外部文件。

## 处理与边界

识别计算没有固定2秒、3秒或15秒任务总时限，后台完成有限的概览、分块、金字塔和小码放大搜索。换源或退出可取消；原生库单次调用不能强行中断，返回后立即检查取消，不发布半份结果。

单张图片最多1.6亿像素、最长边65536像素；每层最多256块、最多4个中间层和512个有效实例。资源预算不是所有尺寸都已验证成功的保证。8K大小混合、16K宽图微小码和高密码分块接缝有真实解码检查；模糊、损坏、屏外信息及平台私有码仍可能无法识别。原图和文件不修改。

微信准备、等待与计算不再共享入口两秒总期限；微信控制器开始后共用两秒输入期限，提交后只读观察至多十秒；目标身份、证据新鲜度和一次提交保护继续保留。只读等待退避观察，无进展终止为未确认，不无限重试输入。微信原生配置目前仅适配4.1.15.13、单屏3200×2000、200%缩放。超出屏幕无法完整显示原图及校验白边时不能无损交付。

标准QR、Micro QR、rMQR及旋转、反色、透明图片可读取。Code 128、EAN-13、Code 39 等常见一维条码使用同一个有限搜索流程；大图长条码增加整行/列条带避免分块截断，同文条码保留独立实例。文字、Wi-Fi、名片等保留内容，不执行系统命令或任意应用协议。微信登录、身份确认、支付与平台不支持业务的限制保留；已知Native付款码在输入前停止。图片输入的微信专用码需先在屏幕显示后框扫。

识别在本机完成，不上传屏幕，历史记录只保存在当前用户本机目录，可关闭或清空，不保存截图和聊天图片。确认打开网址后浏览器会访问该地址；Ctrl+C会写剪贴板。开发人员可显式指定--diagnostics-file记录最后一次固定错误编号，默认关闭，记录不含二维码内容、截图或聊天信息。当前便携版未签名，跨设备兼容与完整微信业务验收状态单独列出，不宣称所有Windows或微信业务已通过。

## 构建和开源

普通用户：完整解压便携 ZIP，运行其中的 `ScreenQR.exe`，无需 Python、手机或安装驱动。不要只复制 EXE；帮助和自测清单在程序内 F1。`F1 → 保存环境报告` 或 `tools/环境检查.cmd` 可一键输出本机报告，由用户决定是否分享，不会自动上传。

开发者：使用官方 **Python 3.12.10 x64**，安装 `requirements-dev.txt` 后运行 `main.py`；`build.ps1` 先运行源码检查，再构建、比对冻结模块和源码、生成元数据及整包 `SHA256SUMS.txt`。Pillow 12.3.0、ZXing-C++ 3.1.1、PyInstaller 6.22.2 固定。`main.py --image 路径` 输出 JSON，不打开内容。包内公开合成格式与大小样本不是有效登录、群邀请或订单凭据。

开发验收工具 `tools/run_stability.py` 在真实桌面显示公开样本，用实际 EXE 测 100 次循环与 30 分钟持续扫描；产品处理耗时、扫描等待与框架耗时分开。该模式不测试微信业务、禁止浏览器和微信提交，普通启动不写性能日志。重新运行属于新的验收，不能继承历史结论。

## 下载来源与费用

项目不要求购买证书。当前便携版**未签名**；Windows 或企业策略可能提示或阻止运行，开源和校验码都不等于安全认证。先核对可信下载来源、发布页 ZIP 校验码及程序 F1 的实际 EXE 校验码。不要为运行本程序关闭防护或安装自建根证书。

GitHub Actions 使用固定官方动作提交，执行 Windows 检查、打包、冻结模块与源码比对、整包校验和 ZIP 来源证明。具体运行及证明以 Actions 中对应的提交和文件哈希为准。`.gitattributes` 保留原始文件字节，避免 Windows 检出时自动换行导致源码校验不一致。首次构建的 407 项检查通过，另行字节比对发现了换行变化；修复后的运行单独记录，不倒写首次结论。

云端构建与本机已验收 EXE 分开报告。本机包没有云端构建证明，云端来源证明也不代表完成了本机 GUI 或微信业务验收；两者都不代替 Windows 数字签名。免费签名可申请 SignPath Foundation，需审核，不承诺获批。详见[免费分发与签名方案](docs/免费分发与签名方案.md)。历史文档保留发布前的记录，当前公开及构建状态以本仓库和对应运行记录为准。

目标平台为 Windows 10（2004 起）/11 x64；目前实际本机为 Windows 11、单屏 3200×2000、200%。普通扫码的多屏和常见缩放有坐标保护及检查，但其它真机仍待验证。微信只适配 4.1.15.13 及上述单屏设置，错配会停用微信通道，保留普通扫码。不保证 Windows 7、32 位、ARM64、云电脑、远程桌面或受保护画面。
