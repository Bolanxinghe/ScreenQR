# 微信二维码分类与测试矩阵

更新：2026-10-21。此表是业务覆盖清单，不把一张示例码当作整个业务通过。业务用途与二维码外形不是一一对应关系；同一H5或小程序可以承载很多业务，新增业务继续登记。

## 通过标准与状态

- 解码通过：程序保留原始内容并给出正确处理路径，不等于业务有效。
- 入口通过：真实电脑操作打开正确初始页或预览，随后关闭，不执行关注、入群、付款、登录确认、领券或核销。
- 历史入口通过：已有同类型代表样本的真实记录；不重复私有码，不外推到该类所有实例。
- 格式样本：自行编码的测试字符串。没有平台签发的令牌、签名或订单，禁止把它写成有效业务码或用它判定业务兼容。
- 待有效样本：必须由账号持有人、开发后台或商户签发；没有凭据时不伪造通过。
- 平台限制：公开文档说明入口或设备限制；能解码不等于当前Windows微信能够办理该业务。
- 不适用打开：文字、Wi-Fi等没有网页业务入口，验收正确显示/复制即可，不擅自执行系统操作。

## 分类型清单

| ID | 功能与子类型 | 有效样本如何产生 | 当前入口状态／验证边界 |
|---|---|---|---|
| C01 | 个人微信名片码 | 本人或明确授权测试账号展示自己的二维码 | 待有效样本；只看名片，不加好友 |
| C02 | 普通群邀请二维码 | 群内有权限者生成的有效邀请 | 用户指定代表样本历史入口通过；不进入群聊 |
| C03 | 更新、过期或需批准的群邀请 | 同一授权测试群的不同状态 | 待状态样本；识别过期提示不等于正常入群通过 |
| C04 | 企业微信联系人／联系我 | 企业后台或联系人生成 | 待有效样本；企业微信客户端能力单独记录 |
| C05 | 企业微信客户群／进群方式 | 企业后台签发 | 待有效样本；不让其他群聊参与测试 |
| O01 | 公众号主页／关注名片码 | 公众号后台或官方公开名片 | 待官方公开有效样本；不点击关注 |
| O02 | 公众号临时带参数码 | 开发后台签发ticket | 待签发样本；格式码不能证明ticket有效 |
| O03 | 公众号永久带参数码 | 开发后台签发ticket | 待签发样本；不能从随机字符串生成真实关注或绑定能力 |
| O04 | 公众号文章／已公开H5 | 有效公开文章网址转换为标准QR | 普通网页机制已有历史实测；文章代表页待本批验证 |
| V01 | 视频号主页码 | 视频号官方分享入口生成 | 待有效公开样本；不关注 |
| V02 | 视频号内容分享码 | 对应内容分享入口生成 | 待有效公开样本；不点赞、评论或播放操作 |
| V03 | 视频号直播／预约码 | 有效直播或预约页面生成 | 待有效公开样本；不预约或进入互动 |
| M01 | 小程序正式版圆形小程序码 | 小程序服务端／云调用 | 官方组件示例历史入口通过；不外推全部应用 |
| M02 | 小程序不限量scene码 | 开发后台签发 | 待独立有效scene样本；与M01可共用外形，不能仅凭图案判断接口 |
| M03 | 小程序普通方形二维码 | 开发后台签发 | 待有效样本；自行给普通网址画QR不能冒充此类 |
| M04 | 开发工具预览码 | 开发者工具当前会话生成 | 待有效样本及测试权限；不得绕过开发者身份限制 |
| M05 | 体验版／权限限定码 | 小程序体验版后台生成 | 待有效样本；无权限应正确反馈，不能记业务成功 |
| M06 | 配置过跳转规则的普通链接码 | 自有域名且后台已配置规则 | 待已配置规则的有效样本；普通网址样本只证明网页打开 |
| M07 | 小程序URL Link转二维码 | 官方接口签发有效链接 | 待有效签发链接；桌面与移动端能力分开 |
| M08 | 小程序URL Scheme转二维码 | 官方接口签发有效scheme | 格式与不误执行检查通过；真实打开待有效签发样本 |
| W01 | 普通HTTP/HTTPS网页 | 自建本机页面或公开页面生成 | 本批真实桌面经微信打开准确本机H5，访问一次后关闭；HTTPS公网机制不混算此例 |
| W02 | 中文、参数、短链、重定向网页 | 自建服务器生成可核验最终页 | 中文、参数、片段格式解码通过；含中文参数的本机H5入口通过；302最终页仍待真实打开验证，短链待样本 |
| L01 | Windows微信自身登录码 | 电脑客户端当前登录会话签发 | 解码不等于具备已登录手机身份；不承诺免手机登录 |
| L02 | 网站微信扫码登录 | 已登记应用与当前登录会话签发 | 待自有测试应用；不自动确认登录或账号授权 |
| L03 | 公众平台／开发平台／商户后台登录 | 对应平台当前会话签发 | 待授权测试会话；认证操作由用户完成 |
| L04 | 账号绑定、设备登录或OAuth授权码 | 自有测试服务签发并配置回调 | 待有效样本；扫码可能触发事件，不能假定只打开无副作用 |
| P01 | 个人收款码 | 本人的收款入口生成 | 待专用测试样本；不访问其他人的收款账户 |
| P02 | 商户静态收款／JSAPI页面码 | 自有商户后台生成 | 待商户专用测试码；只验证收银台初始页，不付款 |
| P03 | Native订单支付码 | 商户下单返回code_url | 官方限制相册/长按识别；两种已知协议格式解码通过，产品在原生输入前拦截并说明限制；未建立真实订单 |
| P04 | 用户出示的动态付款码 | 钱包实时生成，由商户被扫 | 不收集真实付款码；不是本工具打开网页的使用场景 |
| P05 | 转账、赞赏、红包等入口 | 对应官方业务签发 | 待无资金测试入口；不领取、不转账、不创建实际资金行为 |
| P06 | H5／小程序内支付入口 | 有效网页／小程序及商户配置 | 页面打开与支付能力分别验收；支付确认不执行 |
| T01 | 优惠券／会员卡领取码 | 业务或商户签发 | 待专用测试券；可能消耗或自动领取，未验证前不扫描 |
| T02 | 核销码／验票码 | 专用测试订单签发 | 不使用私人票证；扫码可能消耗权益，不与普通打开混测 |
| T03 | 乘车码／门禁／凭证出示码 | 业务平台实时签发 | 被扫凭证，不是浏览器入口；不生成可冒充的真实凭证 |
| T04 | 签到／停车／点餐／排队／服务预约 | 自建测试H5或小程序生成 | 以承载入口分类；只开初始页，不签到、下单或预约 |
| D01 | 标准Wi-Fi二维码 | 自建测试网络字符串 | 本批真实屏幕解码通过；旧版有复制实测，本版不外推完整复制专项；不更改网络设置 |
| D02 | 普通文字／名片／电话／邮件／位置 | 自建无真人信息的测试内容 | 本批真实屏幕文字、虚构vCard解码通过；MECARD、电话、邮件、短信、位置图片解码与路由通过，未执行外部动作 |
| D03 | 设备配网／激活／绑定码 | 自有设备厂商或测试后台签发 | 待可撤销的测试设备；不假定扫码无副作用 |
| X01 | 其他专有图形／未知协议／业务短码 | 由实际业务提供方生成 | 显示已知内容或明确未识别；不猜测执行任意系统协议 |

## 当前实施顺序

1. 自建标准QR的真实解码、处理路径与拒绝边界；生成样本清单注明格式样本与有效业务样本。
2. 真实桌面扫描本机H5、重定向及非网页内容，确认实际结果，不用直接喂图代替桌面验证。
3. 复用已有官方小程序和授权群码的历史证据；新增公开有效样本后再扩大公众号、个人名片、视频号等入口验证。
4. 账号、商户或开发权限缺失的类型保留待测，不能以随机令牌、过期样例或接口存在冒充通过。

QR Model 1/2、Micro QR、rMQR、圆形小程序码属于编码／外形层；它们不等同于上述业务用途。商品条形码、摄像头翻译、识物等属于不同功能，本表不把它们充当二维码类别。

## 核实来源与限制

- [腾讯官方微信产品概览](https://www.tencent.com/zh-cn/products/weixin-wechat/)：说明公众号、小程序、视频号等生态；上述表格是本项目的测试分解，不宣称官方提供过穷尽清单。
- [微信支付Native产品介绍](https://pay.wechatpay.cn/doc/v3/merchant/4012791874)：code_url由商户订单产生，明确限制相册及长按识别。由此推断当前截图识码不能承诺等同摄像头扫一扫，不把推断写成Windows逐码实测。
- [微信支付通用支付产品](https://pay.wechatpay.cn/doc/v3/merchant/4012068590)：区分用户出示付款码、Native、JSAPI、App、小程序支付。付款码不是普通扫码打开链接。
- [腾讯云开发获取小程序码](https://docs.cloudbase.net/lowcode/practices/miniapp-guide/get-qrcode)：展示云调用获取真实小程序码。本文依据官方检索内容核实，网页正文抓取暂受限。
- 微信开放文档的公众号参数码与小程序接口页面抓取暂受限；临时／永久、预览／体验等作为待核实和待样本的测试分项，不据此编造有效码或当前数量限额。

测试不发送微信消息；新业务入口打开后关闭，不进入后续操作。浏览器和微信页面结果、HTTP访问计数、代码检查分别记录。任何平台限制或无样本项均不记为通过。

本轮详细证据和未完成项见[微信分类实测报告](微信分类实测报告-2026-10-21.md)。用户已选择先用公开和自建样本；无自有账号签发码时，参数公众号码、个人名片、视频号等项目继续保留待测，不使用无效令牌凑通过数量。
