# 不购买签名的分发方案

核实日期：2026-10-26。当前选择：零费用的未签名便携包，保留 MIT 开源许可。没有购买证书、安装根证书、申请第三方服务或发布 GitHub。

## 现在实行

1. 只从明确的官方仓库及 Releases 分发完整 ZIP，保留 `_internal`，不要单独转发 EXE。没有既定仓库地址前不编造“官方地址”。
2. 随包提供完整文件 SHA-256 清单，程序 F1 → 关于显示运行中 EXE 的实际校验码；“检查文件”在本机核对。发布页另外公布 ZIP 与 EXE 校验码。攻击者能同时替换文件与清单，故仍须核对可信发布页。
3. 固定 Python 3.12.10 和既有依赖版本，先通过源码检查，再构建并逐个比对冻结模块。构建信息只记录本次事实，不继承旧版真机通过结论。构建不是逐字节可重复的承诺。
4. 已准备 GitHub Actions：只读构建检查、固定官方动作提交；受信任分支/标签的独立任务为 ZIP 生成构建来源证明。第一次云端运行及验证尚待仓库发布后完成。本地包没有这份云端证明，不能冒充 Actions 产物。
5. GitHub CLI 可用 `gh attestation verify 文件.zip -R 所有者/仓库` 核对未来的云端产物。普通使用者只需完整解压、运行 EXE，在程序内看说明、核对文件或保存环境报告。

GitHub 来源证明在免费账户的公开仓库可用，证明构建关联，不是 Windows Authenticode 签名，也不是无病毒证明。[GitHub 官方文档](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations)

## Windows 提示的真实边界

未签名程序可能显示发布者未知；部分企业策略或 Smart App Control 会直接阻止。自签证书通常仍会警告，不让朋友安装自建根证书，不建议关闭系统防护。有效商业签名也不保证新文件立刻免提示，EV 也没有这项保证。程序内已移除“未签名所以不是病毒”与无条件放行的说法。[Microsoft 官方说明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)

## 免费签名：等项目公开后再申请

SignPath Foundation 为符合条件的开源项目提供免费代码签名。需要已发布、持续维护、功能有文档、可核验构建、遵循审核和发布批准流程等条件；批准不保证，证书发布者是基金会。ScreenQR 可以准备申请，但现在不能标注“由 SignPath 签名”，也不能伪填审核人员和政策承诺。后续签名会改变 EXE 哈希，需要重新生成清单并复核最终包。[申请条件](https://signpath.org/terms.html)

微软商店是另一条长期路线：新注册入口目前免注册费，仍需身份核验、打包与审核，免费注册不等于应用已经获准。商店分发的 MSIX 与 GitHub ZIP 是不同交付方式，后者不会因此自动取得签名。这次不创建账号或上传证件。[微软注册说明](https://learn.microsoft.com/en-us/windows/apps/publish/partner-center/open-a-developer-account)

商业签名作为参考：微软 Artifact Signing 基础档从每月 9.99 美元起，另受身份与地区资格限制；用户已明确不购买，因此不启用、不订阅。[微软说明与价格入口](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)

## 公开前由维护者决定

- 确定 GitHub 账号、仓库名、是否先标测试版，以及哪些已知限制必须放在发布页。
- 在 GitHub 人工开启账号双重验证、分支保护及发布审批。当前没有自动改动账户权限。
- 云端首轮通过后下载 ZIP，核验来源证明，在另一台 Windows 真机运行。未验证项仍写待验证。
- 若愿意，再申请 SignPath 或评估商店；不把第三方审批卡在本次未签名测试包之前。
