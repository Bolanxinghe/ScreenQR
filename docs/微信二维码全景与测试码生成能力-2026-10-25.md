# 微信二维码业务全景与测试码生成能力

核查日期：2026-10-25。

**结论：能画出二维码，不等于能生成微信承认的业务凭证。当前可独立生成标准内容码；真实微信业务码通常需要账号、会话、商户、开发或设备条件。明文小程序Scheme可在后台声明后拼接，是不能一概称“所有链接必须签名”的例外。**

本清单按 11 个业务组、73 个测试用途整理。它们不是 73 种独立二维码制式。同一网页/小程序码可以承载许多用途；第三方业务持续新增，微信没有被本次核实到的“所有功能有限穷尽表”。尚未逐项核实的客户端行为与后台资格明确待测。

## 怎么判断能否生成

| 标记 | 当前能做什么 |
|---|---|
| SELF | 现在可生成真实通用内容码 |
| OWNER | 需账号/内容持有者从官方入口生成或导出 |
| API | 具备业务权限后，可通过官方接口/工具生成 |
| BACKEND | 需对应业务后台或服务商专用测试环境 |
| PRESENTED | 由官方/业务系统签发的出示凭证，不能凭空生成有效码 |

“有条件可生成”表示能够在合法权限与测试资源到位后协助开发和调用；本次未登录业务后台、未请求任何真实业务签发接口，也未取得AppSecret/商户密钥。已经登录普通微信不等于拥有公众号、小程序或商户接口权限。

| D02 | 打印机、物联网设备等配对/绑定码 | BACKEND | 设备方签发的序列号/nonce/会话或测试后台 | 绘制虚构内容不能完成真实绑定，不打印或绑定；来源 [mini](#mini)、[ecosystem](#ecosystem) |
| D03 | 电视、车机、电脑或硬件的登录接力码 | BACKEND | 对应服务当前官方会话与明确设备范围 | 与微信PC自身登录码、游戏码分开，不确认登录；来源 [login](#login)、[ecosystem](#ecosystem) |
| D04 | 门禁、身份核验、人脸核身业务的接力入口/出示码 | BACKEND | 服务方测试身份和设备/会话；视业务为链接或凭证 | 二维码不是人脸活体或身份验证本身，不伪造身份凭证；来源 [mini](#mini)、[ecosystem](#ecosystem) |

## 编码形式、业务状态与承载入口分开

- 标准方形QR可以装网址、文字、数据或协议字符串；微信圆形小程序码是WX_CODE一类专用码，不能把普通QR画圆或加logo来代替。
- URL Link、Scheme、Short Link是入口内容，不是三种新的图形编码。Short Link文本可用不代表直接生成QR后一定可扫码打开。NFC、扫一扫识物/翻译、商品条形码、wx.login临时code、人脸活体都不自动算独立二维码类型。
- 静态/动态、临时/永久、过期/撤销、正式/体验/开发、需登录/需身份、相机限定/可图片识别，是横跨业务的状态或入口限制。
- 一个二维码中带了“微信”字样，或者显示在微信窗口中，不能决定分流；反之显示在浏览器里的二维码也可能是微信专用业务。

## 当前样本资源与核查结论

- 自建格式样本：25张既有生成规则会在本次样本包重建并逐张解码核验，包含微信群路径、微信协议、Native支付和登录确认格式。这些特殊业务样本均无有效平台凭证，禁止用来证明业务接受或进行业务打开。
- 公开网页样本：另生成2张实际公开资料URL的标准QR；它们是网页测试，不是公众号关注、小程序或登录凭证。
- 官方小程序：从官方作者仓库引用的原始图片复用，不自行签发或仿画。项目历史已有正确初始页实测；本轮不把资料读取算成新实测。资源获取结果、原样哈希与旧样本是否一致见 samples-manifest.json。
- 授权只读查找：当前浏览器原有标签是此前本机测试页；指定会话近期图片可见游戏登录码、课程海报码、软件演示图片。未将私人图片、聊天正文或二维码载荷导出到本报告。海报用途不能替代真实载荷分类；旧码可能过期。此为有针对性的查看，不是全量聊天审计。

## 与ScreenQR当前问题直接相关的发现

1. **网站微信快速登录**：官方文档说明，符合要求且已登录、未锁定的桌面微信可供网站应用快速登录，无需扫码。它是网站官方登录流程，不能由任意旧二维码反推出，也不能直接外推到摄像头限定游戏授权。此能力值得单独验证；本次没有执行登录。
2. **Native支付限制**：官方文档明确要求扫一扫，不支持相册/长按方式完成。限制不能外推到全部个人收款、商户H5或所有二维码。
3. **公众号参数码可能产生回调**，即使只扫码未关注也须按账号状态与后台配置考虑，不当作纯静态网页。
4. **付款码、乘车码、会员/券核销码是出示凭证**，经常需要另一端设备/商户后台处理；“在浏览器里打开”不是正确验收目标。
5. **生成条件与Windows兼容是两件事**。签发有效码之后，还需按真实客户端验证是否打开正确首页；无效码能被解码、显示链接或出现窗口都不代表业务通过。
