# Windows兼容性：设计范围与用户自测

更新：2026-10-20。按用户要求，开发方负责理论设计/代码适配，用户负责真实跨系统和设备测试。下面所有未实际测过的组合均为“待用户验证”，不宣称通过，也不作为本机核心开发的等待条件。

## 理论设计

基础扫码器目标为Windows10 2004及以上、Windows11、x64。使用DPI感知进程和物理像素坐标；虚拟桌面允许负坐标。捕获、显示和二维码输入保持原图尺寸。32位、ARM64暂未适配。

微信原生适配须与基础扫码器分开声明。目前研究配置仅为微信4.1.15.13、单屏3200×2000、200%DPI；版本、界面或显示配置不合条件时应明确拒绝自动提交。不能把未知版本当作已适配，也不应在失败时尝试任意按钮。

布局、DPI、屏幕拓扑或取景来源变化使旧帧失效。多屏混合DPI和跨屏拖动必须重新取得映射；失败应给出可理解的提示，保留取消，不能继续用旧坐标。受保护画面、安全桌面或不可见目标不得冒充识别成功。

## 用户自测清单

每个有条件测试的环境记录系统版本、CPU架构、微信版本、屏幕数/分辨率/缩放及结果；不要求为了测试购买设备。

| 场景 | 通过标准 | 当前状态 |
|---|---|---|
| Windows10 / Windows11 x64 | 启动、正常退出；界面和取景可用 | 非本机组合待用户验证 |
| 100%/125%/150%/200%缩放 | 框内内容与识别/冻结内容相同，没有偏移或裁剪 | 非本机组合待用户验证 |
| 多屏、负坐标、混合缩放 | 在各屏及跨屏移动后重新取景；旧请求失效 | 待用户验证 |
| 改分辨率、插拔屏幕、睡眠恢复 | 能重新映射，或明确停止并提示重试；不误提交 | 待用户验证 |
| 干净Windows账户、普通权限 | 依赖随包可用；无法运行时提示明确 | 待用户验证 |
| 微信版本或布局不同 | 未适配时停止原生提交，基础扫码不误称业务成功 | 待用户验证 |

只使用公开测试码或自行指定样本，不提交登录/支付等最终确认。测试“能否打开”后立即关闭页面，不进入内容操作。遇到失败，提供环境信息和复现步骤即可；私人二维码、聊天和凭据无需提供。

这份清单只改变兼容性真测的分工，不免除本机准确性、100次/30分钟稳定性及0.5秒/2秒目标。
