# 0.9.0-p1-dev：环境适配阶段

本阶段承接工作目录的最新源码，保留桌面 0.8.4 旧包及个人码、支付码分流等后续修复。只做 P1；历史记录、一维条码、多码点选和结果按钮属于下一阶段，未经确认不进入 P2。

## 改动与判定边界

微信版本、屏幕、DPI、窗口身份和工具栏/边界校准集中到 `assets/native-profiles.json`，数据先经过大小、字段、类型、范围、重复项、路径、模型及颜色检查，再转为不可变配置。损坏或未知项禁用微信通道，不把后备常量当作启动许可。首次迁移维持原条件、判定顺序、严格像素比较和单次提交；每个请求绑定独立配置上下文，线程间不串用坐标。

仅携带已校准的微信 4.1.15.13 / 单屏 3200×2000 / 200% 配置。新配置在 strict-v1 已支持的结构内可以加载；这不等于其他版本已真测。其他绘制模型、安装路径或不同结构仍须开发与校准，不通过增大容差冒充兼容。实验模式与联网更新未实现，未产生新的联网行为。

按本次要求，默认微信控制器开始后共用两秒输入期限，不逐操作续期；普通二维码计算不设这类总时限。消耗一次提交后，观察期限从该提交起算至多十秒，只读观察不能恢复输入。付款码、未知输入、多码、来源/实例/新鲜度检查保留。

普通扫码取像前后复核实际屏幕布局和自有窗口 DPI，发布与打开前再次复核。只监听自有窗口的显示、缩放和恢复消息，变化立即撤销旧代次；定期只读探测作补充。框跨在不同屏幕时先停止，完整移入一块屏幕后重新取景；不猜测另一块屏幕的缩放。负坐标保留。微信仍只在匹配的单屏配置中启用。

原有不可变微信原图的完整显示、保护留白、独立选区、工具栏唯一候选和晚到结果保护保留。受保护画面与普通空白不能仅按颜色区分；缺乏可靠显示事实时停止，提示换普通桌面，不假称二维码已扫到。

## 控件变化

改前为取景框、状态、网址预览及“确定”。P1 保留这些，增加短的微信可用性说明；F1 或顶栏右键可打开帮助/关于。没有增加实验按钮、微信开关或重复预览。底栏为两行状态预留空间，支持较小窗口；帮助页可滚动。

所有必要范围说明、快捷用法和失败处理都写入 EXE 页面，用户无需阅读本文。没有宣称未签名程序一定安全，也未要求自动绕过 Windows 的保护。

## 验证

本阶段真实 EXE 结果、源文件/配置/EXE 哈希及交付状态以 `build-info.json` 的本版记录为准。代码与合成布局检查分别记载，不能当成其他显示设备的实测。

待用户真机：Windows 10；100%/125%/150%；负坐标多屏与混合缩放；跨屏拖动；改分辨率、热插拔和睡眠恢复；不同显卡/远程桌面。受控错配配置测试不等于在这些电脑上实测。P1 不证明所有微信业务可用。

只读诊断：最终 EXE 的 `--environment-check` 或 `tools/probe_environment.py` 只输出系统位数、屏幕几何/当前窗口缩放、微信文件版本及配置匹配结果，不采屏、不读取聊天、不输入、不联网。
