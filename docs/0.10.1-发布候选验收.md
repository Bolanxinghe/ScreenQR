## 100 次与 30 分钟真实桌面测试

100/100 个公开样本得到正确可见结果，成功率 100%。80 个 QR、10 个 Code 128、10 个 Code 39，包含小至每模块 1 像素、不同尺寸及旋转。成功定义是每个样本最终正确显示，不声称每个初始捕获帧都成功，也不代表任意损坏图片都能扫。

| 耗时 | P50 | P90 |
| --- | ---: | ---: |
| 产品：抓屏开始至结果发布后的 Tk 空闲点 | 140 ms | 156 ms |
| 其中扫描计算 | 16 ms | 31 ms |
| 测试板显示提交至框架观察到结果 | 305 ms | 360 ms |
| 其中结果发布后框架读到日志的尾延迟 | 31 ms | 47 ms |

产品时间包含正常抓屏和显示流程，不含性能文件写入，不等同屏幕物理发光时间。端到端包含下一帧等待及轮询；样本生成/呈现共 570 ms、框架主动读日志共 1091 ms 单独记录，不冒充产品时间。扫描计算 P90 31 ms 满足历史 0.5 秒目标。微信两秒是输入保护预算，不是本轮实测业务办理耗时。

真正持续扫描 1800.031 秒，5,558 个正确帧，最大界面心跳间隔 1.141 秒，私有内存前后中位数增长 3.72 MiB，工作集峰值 128.22 MiB；平均 CPU 用量相当于 0.243 个逻辑核心。无异常退出，错误输出为空。预先设定的 100 个正确结果、30 分钟、P90 产品≤1秒/端到端≤2秒、心跳≤5秒、内存增长≤50MiB、≥0.5帧/秒均达到，不事后提高门槛。

使用同一最终 EXE 的显式计时入口；普通抓屏、扫描、显示和历史流程实际运行，但该模式禁止浏览器及微信提交。只记录数字与样本序号，无二维码正文、截图或凭据；不是微信业务 30 分钟稳定性验收。普通模式的网页与微信另行实际复核，如上表。

展示板补测曾因开发模块路径缺失退出；只修正测试启动环境后重跑，没有修改产品，原失败日志保留。此失败未计入 100 次正式循环，也未截短挂机时间。
